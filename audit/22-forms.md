# 22 — Form fields

Design values (Contact.dc.html, ClaimListing.dc.html): text/email/tel/select/textarea 1px solid #dbe6f0, radius 10px, padding 12px 14px, Figtree 500 14px, no outline, focus ring "border #0890E8 + 4px rgba(8,144,232,.12)"; claim fields 50px high, radius 14px, 1.5px border, padding 0 16px, Figtree 500 15.5px, error border #e0787c; checkbox accent #0890E8; placeholders #8a9bb0.
Where each form is: Contact (name, email, phone, org, province select, message textarea, callback checkbox) and ClaimListing (search, filter, full name, role, work email, phone) carry the design's inline styles and measure exactly these values in headless Chrome. Promote has no form fields. The sample-route callback forms on Drug/Alcohol/Intervention/Centre are hidden on live pages (no FORM_ENDPOINT).
What was added (src/app/responsive.css §10): the design's field style as a zero-specificity base for every input type, select and textarea (so a control without its own inline style never falls back to the browser look), the focus ring for every bordered control, placeholder colour, `aria-invalid` error border, checkbox/radio accent colour, and a `:-webkit-autofill` override so autofill and extensions cannot repaint the field (white fill, design text colour). Borderless search boxes (inline `border:0`) are excluded, so no layout changes. I could not reproduce the square black "Work email" border in headless Chrome (the field has the design's inline style); the usual cause is browser autofill or an extension, which the override now covers. Please tell me which browser/extension if it persists.
